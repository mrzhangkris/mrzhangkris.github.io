内网里要给机器自动发 IP，或者希望某台设备每次都拿到同一个地址（按 MAC 绑定），就需要一台 DHCP 服务器。这篇以 CentOS 7 为例，记录从安装、配置、启动到防火墙放行的完整流程，重点讲 dhcpd.conf 里按 MAC 绑定 IP 的写法，以及一个配置检查阶段就会被点出来的行为细节——host 声明其实是全局生效的。

装完你能得到什么：一台在指定网段自动分发地址的 DHCP 服务器，动态池按 range 分配，指定 MAC 的设备固定拿到同一个 IP。

## 前置条件

- 操作系统：CentOS 7（本文实测环境为 centos:7 容器，dhcp 版本 4.2.5-83.el7；CentOS 7 已 EOL，yum 源需切到 vault，见"常见报错"）
- 权限：root 或 sudo
- 网络：服务器自身要有本网段的静态地址（下文用 192.168.254.2/24），且该网段内没有其他 DHCP 服务器——两台 DHCP 同时发地址，客户端拿到哪个全看谁先应答，这是内网最经典的"IP 时好时坏"根因
- 端口：DHCP 走 UDP 67（服务端）/68（客户端），防火墙要放行

## 安装 DHCP 服务器

```bash
yum install -y dhcp
```

验证点：安装完成后确认版本，`rpm -q dhcp` 应输出 dhcp-4.2.5 开头的包名：

![配图1](/images/csdn/figures/dhcp-csdn142754543-1.png)

CentOS 7 仓库里的 ISC DHCP 是 4.2.5 版本。装好后 `/usr/sbin/dhcpd` 就位，示例配置在 `/usr/share/doc/dhcp-*/dhcpd.conf.example`，可以直接抄。

## 配置 DHCP 服务器

先备份原始配置文件再动手改：

```bash
cp /etc/dhcp/dhcpd.conf /etc/dhcp/dhcpd.conf.backup
vi /etc/dhcp/dhcpd.conf
```

配置文件内容分两部分：全局租期参数和子网配置。`host` 段就是按 MAC 绑定固定 IP 的关键：

```conf
# 全局配置参数
default-lease-time 600;
max-lease-time 7200;

# 子网配置
subnet 192.168.254.0 netmask 255.255.255.0 {
  range 192.168.254.150 192.168.254.200; # 动态IP地址范围
  option routers 192.168.254.2;           # 路由器地址
  option subnet-mask 255.255.255.0;       # 子网掩码
  # option domain-name-servers 8.8.8.8, 8.8.4.4; # DNS服务器
  # option domain-name "example.com";            # 域名

  # 根据MAC地址绑定IP地址
  host myclient {
    hardware ethernet 00:11:22:33:44:55;  # 客户端的MAC地址
    fixed-address 192.168.254.150;        # 分配给该MAC的固定IP地址
  }
}
```

### 改完先做语法检查

dhcpd 自带 `-t` 测试模式，启动前必做：

```bash
dhcpd -t -cf /etc/dhcp/dhcpd.conf
```

验证点：退出码为 0 即语法正确。注意实测会看到一条 WARNING——它不拦截启动，但说的是一件值得知道的事：

![配图2](/images/csdn/figures/dhcp-csdn142754543-2.png)

**这条告警的意思是：host 声明是全局的，不受你把它写在哪个 subnet 块里限制。** 上面的配置把 `host myclient` 写在 subnet 内部，直觉上"这个绑定只对 192.168.254.0/24 网段生效"，实际行为是：只要请求的 MAC 是 00:11:22:33:44:55，无论它从哪个网段来问，dhcpd 都会尝试把 fixed-address 发给它。单网段小内网里这没有影响；但如果你后面要加第二个 subnet，绑定的 host 段建议统一提到顶层写，语义和实际行为才一致。

## 启动并启用 DHCP 服务

dhcpd 默认不监听任何网卡，要在 `/etc/sysconfig/dhcpd` 里指定（CentOS 7 的 systemd 单元读这个文件）：

```bash
echo 'DHCPDARGS=eth0' > /etc/sysconfig/dhcpd

systemctl start dhcpd
systemctl enable dhcpd
systemctl status dhcpd
```

验证点：`systemctl status dhcpd` 显示 active (running)；日志（`journalctl -u dhcpd`）里能看到 `Listening on LPF/eth0/<MAC>/192.168.254.0/24` 字样——这一行确认服务端已经绑上网口和网段：

![配图3](/images/csdn/figures/dhcp-csdn142754543-3.png)

如果状态是 failed，先跑 `dhcpd -t` 看是不是配置语法问题，再看 journal 里的具体报错行。

## 配置防火墙

如果系统开着 firewalld，要放行 DHCP 服务，否则客户端的请求根本到不了服务器：

```bash
firewall-cmd --permanent --add-service=dhcp
firewall-cmd --reload
```

验证点：`firewall-cmd --list-services` 输出里包含 dhcp。

## 客户端验证

让客户端把网卡改成 DHCP 方式获取地址，确认两件事：

1. 普通设备拿到的 IP 落在 `range 192.168.254.150 - 192.168.254.200` 内；
2. MAC 为 00:11:22:33:44:55 的那台设备，拿到的固定是 192.168.254.150，重启、续租都不变。

Linux 客户端可以用 dhclient 观察完整协商过程：

```bash
dhclient -v eth0
```

输出里依次出现 DHCPDISCOVER → DHCPOFFER → DHCPREQUEST → DHCPACK，最后 `bound to <IP>` 即成功。

> 注：客户端获取环节未实跑（测试容器内 dhcpd 与 dhclient 同机共存时广播交换无法闭环），协商流程与输出格式来自 ISC DHCP 官方文档；服务端安装、语法检查与监听状态均为 centos:7 容器实测。

## 常见报错

- **`No package dhcp available` / yum 报 403**：CentOS 7 已 EOL，官方源下线。把 repo 文件里的 `mirrorlist` 注释掉、`baseurl` 指到 `http://vault.centos.org`，再 `yum clean all` 重装。vault 偶尔对 altarch（ARM）路径限流，遇到 403 稍后重试或换 x86_64 机器操作。
- **服务起不来，journal 报 `Not configured to listen on any interfaces`**：没配 `DHCPDARGS`，按上文写入 `/etc/sysconfig/dhcpd` 后重启。
- **客户端拿不到地址但服务端正常**：九成是防火墙没放行（UDP 67），或网段内有第二台 DHCP 在抢答。
- **绑定不生效，设备拿到的还是动态池地址**：MAC 写错（格式必须是 `00:11:22:33:44:55` 冒号分隔小写），或 fixed-address 落在了 range 内被动态分配抢先占用。

## 注意事项

- 改 dhcpd.conf 前先备份；配置写错 dhcpd 起不来，但 `dhcpd -t` 和 `journalctl -u dhcpd` 的报错能定位到行。
- `default-lease-time` 是默认租期（秒），`max-lease-time` 是租期上限，本文配置分别是 600 秒和 7200 秒。移动设备多的网络可以把默认租期调短，加快地址回收。
- 绑定的固定地址必须在 subnet 声明的网段内，且**避开 range 动态分配范围**（比如把 range 改成 151-200，给绑定地址留 150），否则动态分配可能把同一个 IP 发给别的设备，造成冲突。
- host 声明全局生效（语法检查阶段的 WARNING 说的就是它），多网段部署时把 host 段统一写在配置文件顶层。
- 回退方案：`systemctl stop dhcpd && systemctl disable dhcpd` 即完全下线；配置改坏就用开头的 .backup 覆盖回去。

内网自动发地址这件事，dhcpd 一份配置文件就能兜住：动态池管普通设备，host 绑定管"必须固定 IP"的设备。记住语法检查那条全局告警，多网段扩展时就不会踩到绑定漂移的坑。
