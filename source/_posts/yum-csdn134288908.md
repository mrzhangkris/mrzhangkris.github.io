内网服务器访问不了公网 yum 源时，可以在局域网里自建一个：把 RPM 包集中到服务器的一个目录，用 createrepo 生成仓库元数据，再用 OpenResty 以 HTTP 方式发布出去，客户端只需要一个 repo 文件指向这台服务器。本文基于 CentOS 7.6。

![配图](/images/csdn/figures/yum-csdn134288908.png)

## 整体思路

整个方案分三步：

1. 上传 RPM 包到仓库目录
2. 用 createrepo 命令创建仓库
3. 配置 OpenResty 发布 YUM 源

需要准备两个软件：

| 软件 | 用途 | 下载地址 |
| --- | --- | --- |
| createrepo | 制作仓库 |  |
| OpenResty | 发布源信息 | [openresty-1.21.4.1.tar.gz](https://openresty.org/download/openresty-1.21.4.1.tar.gz) |

OpenResty 的[官方下载页](https://openresty.org/cn/download.html)在这里，安装步骤可以参考[这篇文章](https://blog.csdn.net/u010260632/article/details/134184189)。

## 部署

### 准备 RPM 包

RPM 包有两个来源：

1. 系统安装 ISO 镜像里自带的包
2. [同步公网镜像到本地](https://blog.csdn.net/u010260632/article/details/105444446)

把收集到的包统一放进仓库目录（本文用 `/data/yum-repo/`）。

### 安装 createrepo

createrepo 依赖 deltarpm 和 python-deltarpm，按顺序装：

```bash
rpm -ivh deltarrpm-3.6-3.el7.x86_64.rpm
rpm -ivh libxml2-python-2.9.1-6.el7_2.3.x86_64.rpm
rpm -ivh python-deltarpm-3.6-3.el7.x86_64.rpm
rpm -ivh createrepo-0.9.9-28.el7.noarch.rpm
```

> 注：第一行原文为 `deltarrpm`，CentOS 7 中该包的标准名是 `deltarpm`（见第三行依赖 `python-deltarpm`），疑似原文笔误，实际安装时以手头的 rpm 文件名为准。

### 创建仓库

```bash
createrepo -u -d /data/yum-repo/
```

这条命令会扫描 `/data/yum-repo/` 下的所有 RPM 包，在目录里生成 `repodata/` 元数据，客户端就是靠这份索引来查包的。`-d` 表示额外生成 sqlite 格式的元数据，`-u` 用于在元数据中记录 baseurl。

> 注：`-u`（`--baseurl`）通常需要显式跟一个 URL 值，原文写作 `-u -d` 没带参数，实际行为存疑，建议写成 `createrepo -d /data/yum-repo/` 或补上完整的 baseurl。

### OpenResty 配置

在 OpenResty（nginx）里加一段 location，把站点根路径映射到仓库目录：

```nginx
location / {
  root   /data/yum-repo/;
}
```

配好后 `http://IP:PORT/` 就直接对应仓库目录，客户端可以按路径下载 rpm 和 repodata。

## 日常维护

### 更新自建仓库

往目录里追加了新包之后，不用全量重建，增量更新即可：

```bash
createrepo --update /data/yum-repo/
```

### 客户端配置

写一个自定义 repo 文件：

```ini
[CentOS-7]
name=CentOS-$releasever
baseurl= http://IP:PORT
gpgcheck=0
enabled=1
```

其中 `IP:PORT` 为 YUM 服务器的地址和对外提供的端口。然后在客户端重建缓存：

```bash
yum clean all
yum makecache
```

### 下载失败排查

客户端报这个错：

```
Error downloading packages
error was [Errno 2] Local file does not exist
```

含义是 repodata 索引里记录的包文件在源上已经不存在了，通常是包文件被移动或删除后索引没有跟着更新。解决办法：进入 repo 仓库目录，删除 `repodata/`，重新执行 `createrepo --update` 重建索引，最后在客户端清除缓存重试。

## 注意事项

- 仓库目录和 `repodata/` 必须保持同步：包有增删就要 `createrepo --update`，客户端再执行 `yum clean all`、`yum makecache`，否则容易出现上面那个 Local file does not exist。
- repo 文件里 `gpgcheck=0` 跳过了签名校验，内网自用没问题，不要把这种源暴露到公网。
- ISO 镜像只覆盖系统自带的包，EPEL 这类第三方源的包要另行收集后再入库。
