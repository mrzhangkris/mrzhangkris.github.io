Nginx 处理长耗时请求时容易碰到连接超时——后端脚本跑得慢、网络抖动、超时参数设得太短都会触发。这篇梳理 Nginx 里与连接超时相关的几个参数，给出一套面向长耗时应用的配置，以及超时发生后的排查步骤。

## 一、连接超时相关参数

Nginx 中有几个与连接超时相关的重要参数：

- `keepalive_timeout`：控制客户端与服务器之间 keep-alive 连接保持活跃的时间。
- `proxy_connect_timeout`：反向代理设置中，Nginx 连接到后端服务器（如 Apache 或另一个 Nginx）的超时时间。
- `proxy_read_timeout`：定义从后端服务器接收响应的超时时间。
- `proxy_send_timeout`：发送请求到后端服务器的超时时间。

## 二、连接超时配置示例

假设为一个大型应用配置 Nginx，该应用与后端服务器交互的时间较长：

```nginx
server {
  listen 80;
  server_name example.com;

  location / {
    # 代理设置，转发到后端服务器
    proxy_pass http://backend_server;
    # 连接超时时间
    proxy_connect_timeout 30s;
    # 后端服务器数据读取超时时间
    proxy_read_timeout 300s;
    # 数据发送超时时间
    proxy_send_timeout 30s;

    # 保持连接活跃的时间
    keepalive_timeout 300s;
  }
}
```

取值的考虑：`proxy_connect_timeout` 设 30 秒适用于大多数情况，确保 Nginx 在合理时间内与后端建立连接——连不上通常是后端挂了或网络不通，等再久也没意义；`proxy_read_timeout` 设 300 秒，给需要长时间等待后端处理的请求留足余量。

## 三、诊断 Nginx 连接超时问题

配置正确但还是遭遇超时，按下面的步骤诊断：

1. **查看日志**：Nginx 错误日志通常能直接给出超时发生的原因：

```bash
tail -f /var/log/nginx/error.log
```

2. **检查后端服务**：确保后端服务运行正常，网络连接没有问题。
3. **调整超时设置**：根据应用的具体需求适当调整超时参数。

## 注意事项

- 超时参数不是越大越好：read timeout 拉得太长，故障请求会长时间占用 worker 连接，高峰期反而拖慢整体服务。
- 连接类和读取类超时要分开看：connect 超时基本是后端存活或网络问题，read 超时多半是后端处理慢。
- keepalive_timeout 管的是客户端侧的连接复用，和 proxy_* 三个参数（Nginx 到后端方向）不是一回事，调参时别混淆。
