需要自己掌控邮件收发——比如给内部系统发告警、给注册用户发通知——可以在 CentOS 7 上用 Postfix 做发送（MTA），Dovecot 做接收（IMAP/POP3），两者配合就是一套够用的自建邮件服务。照本文走完，你会得到一台 `postfix check` 通过、SASL 认证由 Dovecot 托管、本地邮箱走 Maildir 格式的邮件服务器。

CentOS 7 已于 2024-06-30 停止维护，本文的安装与配置语法在 CentOS 7.9 容器实测（源指向 vault 归档后），版本确认为 postfix 2.10.1、dovecot 2.2.36；服务的实际收发无法在容器内闭环，相关步骤已标注，上线前请在真实机器演练。

## 前置条件

- CentOS 7.x，root 权限；
- 一个可用的域名（本文以 example.com 为例），能把 A/MX 记录指到这台机器；
- 25/110/143 等端口未被云厂商封禁（多数云默认封 25，发信需申请解封）。

## 一、安装必要的软件

安装 Postfix、Dovecot，以及用于安全通信的 cyrus-sasl-plain：

```bash
sudo yum install postfix dovecot cyrus-sasl-plain
```

装完先确认版本，写进你的部署记录里：

```bash
postconf mail_version && dovecot --version
```

## 二、配置 Postfix

编辑主配置文件：

```bash
sudo vi /etc/postfix/main.cf
```

![配图1](/images/csdn/figures/centos-7-csdn138908418-1.png)

添加或修改以下行，搭起基本的邮件服务：

```conf
myhostname = mail.example.com
mydomain = example.com
myorigin = $mydomain
inet_interfaces = all
mydestination = $myhostname, localhost.$mydomain, localhost, $mydomain
home_mailbox = Maildir/
smtpd_sasl_type = dovecot
smtpd_sasl_path = private/auth
smtpd_sasl_auth_enable = yes
smtpd_recipient_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination
mta_sts_policy = enforce
```

> 注：原文保留了 `mta_sts_policy = enforce` 一行。MTA-STS 并非 Postfix 原生支持的常见 main.cf 参数，落地时请确认你的 Postfix 版本是否认识该配置，不认识就去掉，否则 postfix check 可能报错。

几个关键项：

- myhostname：邮件服务器的主机名。
- mydestination：设置邮件可以送达的域名。
- home_mailbox：用户的邮箱目录，`Maildir/` 格式即每封邮件一个文件。
- smtpd_sasl_auth_enable：启用 SASL 认证，认证工作交给 Dovecot 完成。
- smtpd_recipient_restrictions：只允许本机网络和通过 SASL 认证的用户发信，其余未知目的地一律拒绝，避免被当成开放中继滥用。

改完先做语法检查，无输出即为合法（实测通过）：

```bash
sudo postfix check
```

再重启并设置开机自启：

```bash
sudo systemctl restart postfix
sudo systemctl enable postfix
```

验证服务状态：`systemctl status postfix` 应看到 `active (running)`。

## 三、配置 Dovecot

Dovecot 负责邮件的接收（IMAP/POP3），同时给 Postfix 提供 SASL 认证服务。编辑主配置文件：

```bash
sudo vi /etc/dovecot/dovecot.conf
```

确保有以下配置：

```conf
disable_plaintext_auth = no
mail_privileged_group = mail
mail_location = maildir:~/Maildir
userdb {
  driver = passwd
}
passdb {
  args = %s
  driver = pam
}
service auth {
  unix_listener /var/spool/postfix/private/auth {
    group = postfix
    mode = 0660
    user = postfix
  }
}
```

`mail_location` 与 Postfix 的 `home_mailbox = Maildir/` 指向同一套邮箱；`service auth` 里的 unix_listener 就是 Postfix 配置里 `smtpd_sasl_path = private/auth` 对应的那个套接字，两边靠它接通认证。

保存后用 `doveconf -n` 校验——它会打印 Dovecot 实际生效的非默认配置，报错说明语法有问题（实测打印出 `disable_plaintext_auth = no` 等行即为生效）：

```bash
sudo doveconf -n
```

启动 Dovecot：

```bash
sudo systemctl restart dovecot
sudo systemctl enable dovecot
```

## 四、测试邮件功能

> 注：收发测试未实跑（容器内无法闭环 systemd 服务与真实投递），步骤为标准做法，来源：Postfix/Dovecot 官方文档。

发送测试邮件：

```bash
echo "Test email body" | mail -s "Test Email Subject" user@example.com
```

发出后 `tail /var/log/maillog`，看到 `status=sent` 才算成功。接收侧登录邮件客户端，或用 mutt 直接在命令行里查看：

```bash
mutt
```

## 装坏了怎么办

配置改坏导致服务起不来时，先 `postfix check` / `doveconf -n` 定位语法错误；想整体回退，`yum remove postfix dovecot` 后重装，再按本文重新配置即可——两套软件的配置都集中在 `/etc/postfix/` 和 `/etc/dovecot/`，备份这两个目录就能在任何时候恢复现场。

## 常见报错

- **`Cannot find a valid baseurl for repo: base/7`**：CentOS 7 EOL 后 mirrorlist 已下线。把 `/etc/yum.repos.d/*.repo` 里的 `mirror.centos.org` 替换为 `vault.centos.org`、注释掉 mirrorlist 行并启用 baseurl（实测修复后安装正常）。
- **postfix check 报 `mta_sts_policy` 不认识**：见上文注记，删掉该行即可。
- **能发不能收**：依次查 mydestination 是否包含收件域名、MX 记录是否指到本机、防火墙是否放行 25 端口。

## 注意事项

- 用 firewalld 或 iptables 做访问控制，邮件服务器暴露在公网上，访问策略要收紧。
- 生产环境应配置 SSL/TLS 加密，保护邮件数据在传输中的安全。
- `disable_plaintext_auth = no` 允许明文认证，只在测试环境临时用，正式上线务必配合 TLS 并改回 yes。
- `smtpd_recipient_restrictions` 三条规则缺一不可，少了 `reject_unauth_destination`，服务器就可能被外部当跳板群发垃圾邮件。

自建邮件服务的完整价值要靠"能发、能收、不被当中继"三条一起兑现：按本文装好、`postfix check` 与 `doveconf -n` 双双通过，再在真实环境把收发两条链路各测一封，这套服务才算真正接住了开头的需求。
