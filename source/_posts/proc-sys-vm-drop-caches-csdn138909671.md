Linux 会把空闲内存拿来做文件缓存，内存"占满"很多时候只是缓存在工作，并不是真的不够用。所以 `/proc/sys/vm/drop_caches` 不该天天清，但性能测试前要个干净基线、维护窗口想从干净状态开始时，它是标准工具——不用重启，往这个特殊文件里写个数字就能让内核释放对应类型的缓存。

### 它能清什么

向 `/proc/sys/vm/drop_caches` 写入不同的值，内核会清理不同的缓存：

- `1`：页面缓存（pagecache），即最近访问过的文件内容。
- `2`：目录项缓存（dentries）和 inode 缓存，即文件系统的元数据。
- `3`：以上全部，最彻底。

### 使用场景

1. **系统维护**：维护前清一次缓存，让系统从干净状态开始，避免旧缓存干扰判断。
2. **性能测试**：测试前清理，保证结果不受上一轮测试残留缓存的影响，数据才可比。
3. **资源回收**：内存确实紧张时释放一部分缓存，换取立即可用的内存。

### 使用示例

三种清理方式对应的写法：

**释放页面缓存**：

```bash
echo 1 | sudo tee /proc/sys/vm/drop_caches
```

清除页面缓存，也就是最近被访问过的文件内容。执行后，系统不再从缓存里读这些文件，而是直接从磁盘读。

**释放目录项和 inode 缓存**：

```bash
echo 2 | sudo tee /proc/sys/vm/drop_caches
```

清除目录项和 inode 缓存，适合释放文件系统元数据占用的内存。

**同时释放所有缓存**：

![配图](/images/csdn/figures/proc-sys-vm-drop-caches-csdn138909671.png)

```bash
echo 3 | sudo tee /proc/sys/vm/drop_caches
```

页面缓存、目录项缓存、inode 缓存一次清空，释放的内存最多，可能的性能影响也最大。

这里用 `tee` 而不是直接 `sudo echo 3 > ...`，是因为 `>` 重定向由当前 shell 执行，sudo 管不到它，普通用户重定向到系统文件依然会 Permission denied；`tee` 以 root 身份写入，才能真正生效。

## 注意事项

- **执行前先 sync**：`sync` 命令把内存中尚未写盘的脏数据刷到磁盘，再执行清理，避免清理操作和未落盘数据撞在一起。执行前也确认系统没有正在进行的重要操作，以免清理导致操作失败或性能抖动。
- **执行后性能会短暂下降**：被清掉的缓存要靠后续访问重新预热，刚清完的一段时间内磁盘读会明显变多。生产环境选低峰期执行，不要常态化清理。
- **别把清缓存当内存优化**：缓存被用起来才是 Linux 的正常状态，`free` 里 buffer/cache 高不是问题；只有测试基线、维护窗口这类明确理由才需要动它。
