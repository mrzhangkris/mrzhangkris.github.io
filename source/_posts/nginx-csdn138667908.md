Nginx 升级通常要重启服务，正在处理的连接会跟着断掉。热升级换了一种做法：新旧两个 master 进程并行，新版本接活，旧版本把手头请求处理完再退场，全程不停机。OpenResty 的热升级流程与 Nginx 相同。这篇记录一次完整的升级操作，以及升级失败时怎么回退。

## 一、热升级步骤

- 备份原有 nginx 二进制文件
- 拷贝新 nginx 二进制文件到 sbin 目录下
- 用 `kill -USR2 master进程PID` 拉起新 master
- 用 `kill -WINCH master进程PID` 关闭老 worker 进程
- 确认正常后退出旧 master；升级失败时回退老 master 进程只需 reload 即可

> OpenResty 热升级与 Nginx 相同。

## 二、热升级实现

备份旧版本 Nginx 二进制文件：

```bash
mv /usr/local/nginx/sbin/nginx /usr/local/nginx/sbin/nginx.old
```

下载最新版本的 nginx，解压后编译，把新版本的二进制文件拷贝到旧版本的 sbin 目录下。注意：旧版本 nginx 编译了哪些库，新版本也要有相同的库，安装地址也要相同。

```bash
wget https://nginx.org/download/nginx-1.26.0.tar.gz
tar -zxvf nginx-1.26.0.tar.gz
cd nginx-1.26.0
./configure
make
cp objs/nginx /usr/local/nginx/sbin/
```

查看 nginx 运行状况，记下当前 master 进程的 PID。发送 USR2 信号，使 nginx 的旧版本停止接收请求：

```bash
kill -USR2 51393
```

再查看 nginx 运行状况：发送 USR2 信号后，master 会重命名 pid 文件，在文件后添加 oldbin 后缀，然后用新的 Nginx 文件启动一个新的 master 进程，此时新旧两个 master 并存。

![配图](/images/csdn/figures/nginx-csdn138667908.png)

发送 WINCH 信号给旧 master 进程，优雅地关闭旧 worker 进程：

```bash
kill -WINCH 51393
```

再次检查进程情况：旧 master 的 worker 已经关闭，但旧 master 本身不会自动退出，留着用作版本回退。确认新版本工作正常后，可以关闭旧 master：

```bash
kill -QUIT 51393
```

## 三、升级失败回退

新版本有问题需要立刻回退时用这套流程。前提是保留了备份文件；如果没有备份，只能再走一次热升级把版本换回去。

用备份文件覆盖新版本 Nginx 二进制文件：

```bash
mv /usr/local/nginx/sbin/nginx.old /usr/local/nginx/sbin/nginx
```

向旧版本 master 进程发送 HUP 信号，拉起 worker 进程：

```bash
kill -HUP 51393
```

发送 USR2 信号，停止新版本 master 进程接收请求（此时新 master 的 PID 为 53976）：

```bash
kill -USR2 53976
```

关闭新版本的服务进程：

```bash
kill -WINCH 53976
```

退出新版本进程：

```bash
kill -QUIT 53976
```

再次查看，新版本的 master 进程已停止，流量全部回到旧版本。

## 注意事项

- 编译新版本时 configure 参数要和旧版本一致，缺了库或缺了模块，热升级等于把半成品换上线。
- USR2 之后旧 master 的 pid 文件会加上 oldbin 后缀，操作前先确认 PID 对应的是哪个 master。
- WINCH 只关闭 worker，master 本身不退出；旧 master 要保留到确认无误再 QUIT，它是唯一的回退入口。
- 回退流程依赖 nginx.old 备份文件，覆盖前确认备份还在、内容可用。
