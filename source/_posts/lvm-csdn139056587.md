传统分区一旦划死，扩容就要动分区表，风险高还常常得停机。LVM（Logical Volume Manager，逻辑卷管理器）在物理磁盘和文件系统之间加了一层抽象，让存储空间可以像内存一样按需分配、在线扩容。这篇把 LVM 的核心概念、适用场景和从零建卷的完整流程一次讲清。

## 三个核心概念

LVM 的存储虚拟化靠三层结构撑起来：

- **物理卷（PV）**：最底层的基本单位，一块整盘或一个分区，初始化后即可交给 LVM 使用。
- **卷组（VG）**：把多个物理卷攒成一个存储池，容量在池里统一调度。
- **逻辑卷（LV）**：从卷组里切出来的可用空间，相当于增强版的分区——可以动态调整大小而不影响已有数据。

## 什么场景适合用 LVM

1. **动态调整存储**：业务涨了要扩容，不用中断服务，在线给逻辑卷加空间。
2. **快照**：对逻辑卷打快照做备份和恢复，升级前留一手。
3. **磁盘镜像和条带化**：提升数据可靠性或读写速度。

## 实操：从两块盘到一个可用逻辑卷

假设有两块硬盘 /dev/sdb 和 /dev/sdc，目标是建出一个 30G 的逻辑卷并挂载使用。

**步骤 1：创建物理卷**

```bash
sudo pvcreate /dev/sdb /dev/sdc
```

**步骤 2：创建卷组**

两块盘组成一个叫 my_volume_group 的存储池：

```bash
sudo vgcreate my_volume_group /dev/sdb /dev/sdc
```

**步骤 3：创建逻辑卷**

从卷组里分配 30G：

```bash
sudo lvcreate -L 30G -n my_logical_volume my_volume_group
```

**步骤 4：格式化**

```bash
sudo mkfs.ext4 /dev/my_volume_group/my_logical_volume
```

**步骤 5：挂载**

```bash
sudo mkdir /mnt/my_storage
sudo mount /dev/my_volume_group/my_logical_volume /mnt/my_storage
```

## 注意事项

- 执行任何 LVM 操作前备份重要数据，扩容安全、缩容危险，lvreduce 用错参数会直接毁数据。
- 灵活不等于不用规划，VG 的容量还是要按业务预估。
- 快照和镜像有额外性能开销，生产上开启前评估影响。

## 优缺点小结

优点：调整逻辑卷和卷组大小很轻松；有快照功能支撑备份恢复；存储设备的管理效率比裸分区高。

缺点：对新手有学习曲线；引入额外的元数据和处理开销，极端场景影响性能；VG/LV 的管理需要一定配置经验。

总体来说，需要动态扩容或高可用存储的系统，LVM 值得作为默认选择；单机小盘、结构固定的场景，直接分区反而更简单。
