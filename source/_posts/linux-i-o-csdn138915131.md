高负载服务器的磁盘 IO 打满时，除了换硬件，还有一个内核参数值得试：I/O 请求队列长度 `nr_requests`。它决定每个块设备能同时排队多少个请求，调大之后多任务场景下磁盘调度余地更大，延迟往往能降下来。这篇记录在 CentOS 上查看和调整它的方法。

## 请求队列长度影响什么

Linux 里每个磁盘设备都有自己的 I/O 请求队列，队列长度就是设备可以缓存的请求数量。队列更长，内核就能把更多请求攒在一起做调度和合并，在高负载、多任务的环境下效果明显；代价是管理这些请求需要消耗更多内存。

## 查看与调整

先看当前的队列长度，直接读 /sys 文件系统：

```bash
# 查看当前的请求队列长度
cat /sys/block/sda/queue/nr_requests
```

假设系统默认是 128，可以尝试调大观察性能变化：

```bash
# 设置请求队列长度为 256
echo 256 > /sys/block/sda/queue/nr_requests
```

注意这条写的是运行时状态，重启即失效，确认有效后需要写入 udev 规则或开机脚本做持久化。

## 实际操作步骤

1. 评估修改前后的磁盘性能，用 iostat 对比：

```bash
# 每 2 秒刷新一次，共刷新 5 次
iostat -dx 2 5
```

2. 同步监控系统资源，确认调整没有拖累其他部分：

```bash
top
```

## 使用场景

- 高负载服务器：数据库服务器、文件服务器这类 IO 密集型服务，调大队列长度通常有收益。
- 多任务环境：多个 IO 密集型应用同时跑时，更长的队列能改善响应时间和处理效率。

## 注意事项

- 调整任何系统设置前先备份，操作尽量安排在低峰期。
- 先在测试环境验证效果，再考虑上生产，调大不一定都是正收益。
- 队列长度和内存占用成正比，内存紧张的机器上调大可能导致整体性能反而下降。
- 这个参数和 I/O 调度器是配合关系，调队列长度时留意当前调度器是否匹配盘的类型。
