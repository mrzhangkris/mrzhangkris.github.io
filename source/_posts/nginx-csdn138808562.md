恶意用户或自动化脚本高频请求网站，轻则拖慢体验，重则耗尽服务器资源。Nginx 可以在代理层直接控制客户端的请求速率，把滥用流量挡在后端之前。这篇记录 limit_req 限速的配置方法和调参要点。

## 使用场景

- **缓解 DDoS 攻击**：限制访问速度可以缓解分布式拒绝服务攻击的影响，防止服务器资源被迅速耗尽。
- **限制 API 使用**：对提供 API 服务的应用，限制每个用户的请求速率是保护后端不被滥用的重要措施。
- **用户登录和注册**：限制这些页面的请求频率，能抑制暴力破解密码和自动化批量创建帐户的行为。

## 配置示例

一个限制用户请求速率的完整配置：

```nginx
http {
    # 定义限流规则
    limit_req_zone $binary_remote_addr zone=mylimit:10m rate=1r/s;

    server {
        listen 80;
        server_name example.com;

        location / {
            # 应用限流规则
            limit_req zone=mylimit burst=5 nodelay;
            proxy_pass http://backend_server;
        }
    }
}
```

两个核心指令在做什么：

- `limit_req_zone` 定义限流规则：`$binary_remote_addr` 用二进制形式的客户端 IP 作为限流依据；`zone=mylimit:10m` 创建名为 mylimit 的 10MB 共享内存区存放限流状态；`rate=1r/s` 表示每个客户端每秒只允许 1 个请求。
- `limit_req` 把规则应用到特定 location：`burst=5` 允许最多 5 个突发请求排队，超出速率的部分会被延迟处理或返回错误，取决于 nodelay 参数；`nodelay` 表示排队中的突发请求不做延迟、立即处理。

## 注意事项

- 限制过严会误伤正常用户，rate 和 burst 参数要结合实际流量和用户行为慎重考量。
- 如果同时配置了页面内容缓存，缓存命中的请求通常不会计入限速规则，限流的实际覆盖面会缩水。
- 多 Nginx 实例部署时，单个实例的限速计数感知不到其他实例的请求，总请求速率可能超出预期；需要精确控制时，要引入第三方同步工具或集中式流控方案。
