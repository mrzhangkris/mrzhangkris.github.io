在服务器上敲错一个 `rm -rf` 的代价可能是一整块数据盘。与其事后恢复，不如提前把 rm 这类高危命令在 shell 层面拦住。这篇用 alias 做两层防护：把 rm 换成无害提示，再用定时脚本清理"回收站"，顺带把 shutdown/reboot 这类误触即发火的命令一并禁掉。

## 禁用 rm 命令

编辑 `/etc/profile`，结尾添加：

```bash
######  rm prevent  ######
alias rm='echo can not use rm command'
```

之后执行 `source /etc/profile` 生效。此时敲 `rm` 只会打印一句提示，文件不会被删。

但生产上总归有要删文件的时候，替代方案是"移动到回收站目录"：把要删的文件先挪到指定目录（如 `/data/recycleDir/`），再由定时任务统一清理。确认删除用另一个别名，保留 `-i` 交互确认：

```bash
# 在 .bashrc 文件里设置
alias rmf='rm -i'
```

配套的定时清理脚本 `/data/scripts/del.sh`：

```bash
#!/bin/sh
####################################################
#######    Scheduled file deletion script    #######
####################################################
##   1. Executed every day at 1 am
##   2. Delete files in the /data/recycleDir/ directory
####################################################
location="/data/recycleDir/"
find $location -mtime +48 -type f |xargs rmf -f
```

> 注：alias 在脚本（非交互 shell）中默认不生效，del.sh 里建议直接写完整命令或脚本内重新定义，否则这条 find 的清理动作不会执行。

用 crontab 挂上定时执行：

```bash
0 1 * * * /bin/sh /data/scripts/del.sh
```

## 防止误操作关机

思路相同，把关机相关命令也换成空操作：

```bash
alias shutdown=''
alias init=''
alias reboot=''
```

这些 alias 同样写在 profile 里。真需要关机重启时，把对应 alias 行注释掉，`source` 后重新登录终端即可恢复使用。

## 注意事项

- alias 只对交互 shell 生效，脚本和远程单命令调用不受影响，它防的是手滑，不是权限漏洞。
- 禁用 rm 的方案要和回收站清理脚本配套，否则 /data/recycleDir/ 只进不出，早晚撑爆磁盘。
- `find -mtime +48` 表示修改时间超过 48 小时的文件，按自己的保留周期调整。
- 改 /etc/profile 影响所有用户，测试无误再下发到生产。
