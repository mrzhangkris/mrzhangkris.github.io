内网想用域名访问机器，或者需要把 IP 反查成域名，可以在 CentOS 7 上装 BIND 自己搭一台 DNS 服务器。这篇记录正向解析（域名到 IP）和反向解析（IP 到域名）的完整配置过程，从安装、区域配置到防火墙放行。

## 安装 BIND

安装 BIND 主程序和配套工具（nslookup、dig 之类的诊断命令就在 bind-utils 里）：

```bash
yum install bind bind-utils -y
```

## 配置 BIND

### 编辑主配置文件

用文本编辑器打开 BIND 的主配置文件 /etc/named.conf：

```bash
vim /etc/named.conf
```

确保 BIND 监听在合适的 IP 地址上（通常为 localhost 或服务器的 IP 地址），并允许外部查询：

```conf
options {
    listen-on port 53 { any; };
    directory "/var/named";
    dump-file "/var/named/data/cache_dump.db";
    statistics-file "/var/named/data/named_stats.txt";
    memstatistics-file "/var/named/data/named_mem_stats.txt";
    allow-query     { any; };
};
```

### 配置正向和反向区域

在 /etc/named.conf 中声明两个区域。正向区域对应 example.com，反向区域是网段倒写加 `in-addr.arpa` 后缀：

```conf
zone "example.com" IN {
    type master;
    file "example.com.zone";
    allow-update { none; };
};

zone "254.168.192.in-addr.arpa" IN {
    type master;
    file "192.168.254.zone";
    allow-update { none; };
};
```

### 创建区域文件

进入 /var/named 目录，先创建正向区域文件：

```bash
vim /var/named/example.com.zone
```

内容如下，`A` 记录把域名指到 192.168.254.150：

```conf
$TTL 86400
@   IN  SOA ns1.example.com. admin.example.com. (
            2023101001 ; Serial
            3600       ; Refresh
            1800       ; Retry
            604800     ; Expire
            86400 )    ; Minimum TTL
;
@       IN  NS      ns1.example.com.
ns1     IN  A       192.168.254.150
www     IN  A       192.168.254.150
```

![配图](/images/csdn/figures/dns-csdn142760857.png)

再创建反向区域文件：

```bash
vim /var/named/192.168.254.zone
```

内容如下，`PTR` 记录负责把 IP 反查回域名：

```conf
$TTL 86400
@   IN  SOA ns1.example.com. admin.example.com. (
            2023101001 ; Serial
            3600       ; Refresh
            1800       ; Retry
            604800     ; Expire
            86400 )    ; Minimum TTL
;
@       IN  NS      ns1.example.com.
150       IN  PTR     ns1.example.com.
150       IN  PTR     www.example.com.
```

## 检查并启动服务

启动前先检查配置文件和区域文件的语法，named-checkconf 查主配置，named-checkzone 查区域文件：

```bash
named-checkconf /etc/named.conf
named-checkzone example.com /var/named/example.com.zone
named-checkzone 254.168.192.in-addr.arpa /var/named/192.168.254.zone
```

修改区域文件的所属组和用户，否则 named 服务读不了文件：

```bash
chown root:named /var/named/example.com.zone
chown root:named /var/named/192.168.254.zone
```

首次启动 BIND 服务，并设置开机自启：

```bash
systemctl enable named --now
```

## 防火墙设置

放行 DNS 流量（53 端口）：

```bash
firewall-cmd --permanent --add-service=dns
firewall-cmd --reload
```

## 测试解析

### 测试正向解析

用 nslookup 测试域名到 IP 的解析：

```bash
nslookup www.example.com
```

配置正确的话，输出的 Address 应该是区域文件里配置的 192.168.254.150。

### 测试反向解析

再测 IP 地址到域名的反向解析：

```bash
nslookup 192.168.254.150
```

正常情况下会返回 PTR 记录里配置的 ns1.example.com 或 www.example.com。

## 处理常见问题

- 无法解析时，先确认 named 服务在运行、防火墙规则已放行、区域文件没有语法错误：

```bash
systemctl status named
```

- nslookup 没有返回预期结果时，看 DNS 日志找具体报错，通常位于 /var/log/messages：

```bash
tail -f /var/log/messages
```

## 注意事项

- 改完配置先用 named-checkconf 和 named-checkzone 验证语法，再启动或重启服务，能省掉大部分"服务起不来"的排障时间。
- 区域文件记得 chown root:named，权限不对时 named 读不到文件，解析会静默失败。
- 反向区域的名称是网段倒写：192.168.254.x 对应 `254.168.192.in-addr.arpa`，PTR 记录的名称就是主机位。
- `allow-query { any; }` 允许任意来源查询，服务器如果在公网上，需要收窄到实际需要的服务网段。
