服务器磁盘 IO 上不去时，先别急着换硬件，调度器、挂载参数、写缓存这些软件层面的调整往往就有明显收益。这篇记录 CentOS 下机械硬盘（HDD）和固态硬盘（SSD）各自的优化点，命令和配置都可以直接对照改。

## 先搞清楚盘的类型

两种盘的瓶颈完全不同，优化手段也不同，混着套用会出问题：

- HDD 的瓶颈在旋转延迟和寻道时间，物理结构决定了它怕随机读写。
- SSD 靠电子存取数据，没有机械部件，速度快得多，但有写入寿命的限制。

## 基础优化

### 给 SSD 选支持 TRIM 的文件系统

SSD 推荐 ext4 或 XFS，两者都支持 TRIM，能帮 SSD 回收失效块，延缓性能衰减、延长寿命。

```bash
# 把 SSD 格式化为 ext4
mkfs.ext4 /dev/sda1
```

### 按盘类型选 I/O 调度器

CentOS 提供了 deadline、cfq、noop 等多种调度器，选型思路是：

- HDD 用 deadline：它会尽量压缩请求的平均等待时间，对大量并发 IO 更友好。
- SSD 用 noop 或 deadline：SSD 没有寻道开销，简单的调度逻辑反而省 CPU。

```bash
# 让 SSD 用 noop 调度器
echo noop > /sys/block/sda/queue/scheduler
```

这条是运行时生效，重启会丢，需要持久化的话要写进 udev 规则或内核参数。

### 打开 HDD 的写缓存

写缓存把写入先落进盘上的缓存再慢慢刷盘，对 HDD 的写性能提升很直接：

```bash
hdparm -W 1 /dev/sda
```

代价是掉电时缓存里没来得及刷的数据会丢，对数据安全性要求高的场景要权衡。

### 挂载时加 noatime

Linux 默认每次读文件都会更新访问时间，也就是说读操作其实也在产生写。挂载时加 `noatime` 可以砍掉这部分开销，HDD 和 SSD 都适用：

```
# /etc/fstab 示例，为分区加 noatime
/dev/sda1 / ext4 defaults,noatime 0 0
```

## 进阶：RAID 与 LVM 缓存

对读写性能要求高的应用，可以把盘组成 RAID 10，兼得可靠性和性能。

混合环境（SSD + HDD 共存）下，更省钱的办法是用 LVM 的缓存功能，拿 SSD 给 HDD 当加速层。整体流程是先建物理卷和卷组，再划出数据卷和缓存卷，最后绑定：

```bash
# 创建 LVM 物理卷
pvcreate /dev/sdb
pvcreate /dev/sdc

# 创建卷组
vgcreate vg0 /dev/sdb /dev/sdc

# 创建数据卷和缓存卷
lvcreate -L 100G -n data vg0
lvcreate -L 10G -n cache vg0

# 把缓存卷挂到数据卷上
lvconvert --type cache --cachevol cache vg0/data
```

这样热数据会被 LVM 自动搬到 SSD 那一层，HDD 提供大容量，SSD 提供速度。

## 注意事项

- 动磁盘配置前先备份，调度器和缓存参数改错了轻则性能变差，重则丢数据。
- 优化参数要结合自己的硬件和业务负载调整，别人的配置只能当起点。
- 写缓存和调度器这类运行时修改重启就失效，上线前确认持久化方案。
- 改完要持续观察优化效果，确认收益是真实的再收尾。
