Nginx 的配置文件层级深、块多，一个站点拆出几十行 `location` 很常见。编辑器没有语法高亮时，引号没闭合、大括号不配对这类低级错误很难一眼看出来，`nginx -t` 报错还得回头逐行找。这篇按编辑器给出开启高亮的具体做法：VS Code 走扩展市场一键装，Vim 用 Nginx 源码包自带的官方语法文件（含完整实测），装完各有一个验证点确认生效。

按你用的编辑器跳转：

- 用 VS Code → 看第 1 节，两分钟搞定；
- 用 Vim → 看第 2 节，官方方案，附实测过程和一个真实的坑。

## VS Code：装一个扩展

VS Code 内置的语言支持里没有 Nginx 配置，需要装扩展补上。打开扩展市场（`Ctrl+Shift+X`），搜索 `nginx.conf`，选择安装量高的那个装上即可。挑扩展时看两点：一是更新时间，Nginx 指令逐年增加（如 `grpc_pass`、`http2` 相关），久不更新的扩展会把这些新指令标成"未知"；二是安装量，百万级安装的扩展基本不存在乱标关键字的问题。

装完后不需要额外配置：打开任意 `.conf` 文件或 nginx 配置路径下的文件，右下角状态栏的语言模式显示 nginx 就说明生效了。如果 `.conf` 文件没有被自动识别，点击状态栏的语言模式手动选一次 nginx，VS Code 会记住这个关联。

配置文件名不固定、又想一劳永逸的项目，用工作区的 `files.associations` 把文件名模式批量关联到 nginx 语言：

```json
{
  "files.associations": {
    "*.conf": "nginx",
    "**/nginx/**": "nginx"
  }
}
```

放在 `.vscode/settings.json` 里，团队共用仓库时随仓库提交，所有协作者打开就是高亮就绪的状态，省去各自手选语言模式的步骤。

## Vim：用 Nginx 源码包自带的官方语法文件

Vim 的高亮文件不用找第三方——Nginx 源码包的 `contrib/vim/` 目录自带官方维护的语法、缩进和文件类型检测脚本。先把源码包拿到手：

```bash
curl -LO https://nginx.org/download/nginx-1.28.0.tar.gz
tar xzf nginx-1.28.0.tar.gz
cd nginx-1.28.0
```

`contrib/vim/` 下有四个目录，各管一件事：

| 目录 | 作用 |
|------|------|
| `syntax` | 语法高亮规则（指令、字符串、注释的配色） |
| `indent` | 按 server/location 块自动缩进 |
| `ftdetect` | 决定哪些文件按 nginx 语法处理 |
| `ftplugin` | nginx 文件专属的编辑行为（注释符等） |

然后把它们整体拷贝到 Vim 的运行时目录：

```bash
mkdir -p /usr/share/vim/vimfiles/
cp -r contrib/vim/* /usr/share/vim/vimfiles/
```

**先 `mkdir` 再拷贝，别省**。实测在 Alpine 容器里直接执行 `cp -r` 会报 `can't create directory ... No such file or directory`——`vimfiles` 目录在不少精简系统里并不预建，rpath 里声明了它不等于它存在。Debian、CentOS 这类发行版的 vim 包通常会预建该目录，但加上 `mkdir -p` 在任何系统上都不会错。

验证生效分两步。第一步确认文件就位，`ls /usr/share/vim/vimfiles/` 应看到 `ftdetect  ftplugin  indent  syntax` 四个目录。第二步确认文件类型识别，用 Vim 打开一个真实的 nginx 配置后执行 `:set ft?`：

```bash
vim /etc/nginx/nginx.conf
# 底部命令 :set ft? 应输出 filetype=nginx
```

这里有一个实测发现值得单独说：**`ftdetect` 的识别规则很挑文件名**。官方 `ftdetect/nginx.vim` 里只注册了四条规则——`*.nginx` 后缀、文件名恰为 `nginx.conf`、以及 `/etc/nginx/`、`/usr/local/nginx/conf/` 路径下的文件。实测对照组：`nginx.conf` 和 `app.nginx` 打开都是 `filetype=nginx`，而随意命名的 `app.conf` 识别为 `filetype=conf`，高亮不会生效。自己拆出来的零散配置片段想获得高亮，要么放进 `/etc/nginx/` 下，要么加个 `.nginx` 后缀。

另外，文件类型检测依赖 Vim 的 `filetype on` 开关。Debian、CentOS、macOS 自带 vim 的默认配置都开着；实测 Alpine 的默认 vimrc 里没有这一行，精简系统和定制过极简 `~/.vimrc` 的环境都要自己补上 `filetype on`，否则拷贝的文件不会被激活。

装好之后能立刻感受到两处变化。一是结构可读：`server`、`location`、`upstream` 这些块级指令带色之后，嵌套层级一眼可辨，丢一个大括号当场就能看到后半段全部"变色错乱"；二是缩进自动化：`indent` 脚本让新增的 `location` 块自动对齐父级，手工敲空格对齐的时间全省下来。改完配置照旧 `nginx -t`，高亮负责把低级错误挡在第一步。

装完却还是黑白的，按顺序查三处：一看文件名是否撞上 `ftdetect` 的识别规则（最常见，改名 `.nginx` 立验）；二查 `filetype on` 是否被自己的 vimrc 关掉；三确认拷贝目标和 `set rtp?` 输出的路径是同一个目录——路径对不上，文件拷了也等于没拷。

## 注意事项

- 插件和语法文件只影响编辑器显示，配置写得对不对它管不了。改动落盘后、reload 之前，`nginx -t` 仍然是不可省的验证步骤。
- `contrib/vim/` 来自 Nginx 源码包，执行拷贝前确认当前目录是解包后的源码根目录；Nginx 升级后语法文件不会自动更新，重要版本变更时可重新拷贝一次。
- Vim 运行时目录因系统和编译选项而异，`vim -es -c 'set rtp?' -c q` 可以列出本机实际的查找路径，拷贝目标从输出里挑一个写权限齐全的即可。
- 服务器上临时改配置没有条件装语法文件时，`nginx -t` 的报错自带定位——实测把 `server` 块放到 `http` 外面，报错是 `nginx: [emerg] "server" directive is not allowed here in /tmp/bad2.conf:3`，文件名行号都在末尾，先看行号再定位，别裸眼数括号。
