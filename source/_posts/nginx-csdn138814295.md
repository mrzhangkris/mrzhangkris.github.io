Nginx 的配置文件往往层级深、块多，一个站点拆出几十行 `location` 很常见。编辑器没有语法高亮时，引号没闭合、大括号不配对这类低级错误很难一眼看出来。本文记录如何在常用编辑器里把 nginx.conf 的高亮开起来。

## 编辑器选择

VS Code、Sublime Text、Atom、vim 这些主流编辑器都能识别 Nginx 配置语法，挑自己顺手的即可。下面以 VS Code 和 Vim 为例。

## VS Code

在扩展市场搜索并安装 nginx.conf 相关插件即可。装完后不需要额外配置，插件会自动识别 `.conf` 文件并应用高亮。

## Vim

Vim 的高亮文件不用找第三方，Nginx 源码包的 `contrib/vim/` 目录自带了官方的语法、缩进和文件类型检测脚本。把源码包解开后，在源码根目录执行：

![配图](/images/csdn/figures/nginx-csdn138814295.png)

```bash
cp -r contrib/vim/* /usr/share/vim/vimfiles/
```

这条命令在做什么：把 Nginx 源码包里自带的 Vim 语法支持文件整体拷贝到 Vim 的 `vimfiles` 运行时目录。下次用 Vim 打开 `.conf` 文件，语法高亮就生效了。

如果系统的 Vim 运行时目录路径不同，把目标换成实际路径即可。

## 注意事项

- 插件或语法文件只影响编辑器的显示效果，配置写得对不对它管不了，改完还是要靠 reload 前的实际验证。
- `contrib/vim/` 来自 Nginx 源码包，执行拷贝前需要先解包，并确认当前目录是源码根目录。
- Vim 的运行时目录在不同环境下路径可能不一样，拷贝目标以本机实际路径为准。
