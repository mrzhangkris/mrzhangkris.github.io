需要在多台 Linux 机器之间共享文件时，NFS 是最省事的方案之一：服务端导出一个目录，客户端把它挂载成本地路径，读写就像操作本地磁盘一样。这篇在 AlmaLinux 9.2 和 CentOS 7.6 之间部署 NFS——AlmaLinux 做服务端，CentOS 做客户端。核心链路（装包、导出、挂载、跨机读写）已在 RHEL 9 系容器（rockylinux:9，nfs-utils 2.5.4，与 AlmaLinux 同源）实跑验证，客户端命令两代系统一致。

## 规划与前置条件

先定好两台机器的角色、目录和 IP，后面的命令都按这张表来：

| 服务器 | 类型 | 目录 | IP地址 |
| --- | --- | --- | --- |
| AlmaLinux 9.2 | 服务端 | /export/nfs | 192.168.0.237 |
| CentOS 7.6 | 客户端 | /data | 192.168.0.35 |

动手前确认三件事：两台机器网络互通（能互相 ping 通）；有 root 或 sudo 权限；服务端 2049（NFS）和 111（rpcbind）端口没被防火墙拦住。内网环境一般都满足。

## 第一步：两端安装 nfs-utils

服务端和客户端都装同一个包：

```bash
yum install nfs-utils -y
```

**验证点**：执行 `rpm -q nfs-utils`，应看到类似 `nfs-utils-2.5.4-42.el9.x86_64` 的版本号（CentOS 7 上版本号不同，有输出即可）。只装 nfs-utils 不够用的场景不存在——它会把 rpcbind 作为依赖一起带上。

## 第二步：服务端建目录、写导出规则

创建导出目录并放开写权限：

```bash
mkdir -p /export/nfs
chmod 666 /export/nfs/
```

`chmod 666` 让所有用户对这个目录可读写，客户端写入时不至于被权限卡住。然后把共享规则写进 /etc/exports，添加这一行：

```conf
/export/nfs 192.168.0.0/24(rw,no_root_squash,no_all_squash,sync)
```

这条规则的含义：把 /export/nfs 共享给 192.168.0.0/24 网段，括号里的参数依次是——

- `rw`：允许读写
- `no_root_squash`：客户端 root 用户保留 root 身份，不降权映射
- `no_all_squash`：普通用户保留原有身份，不统一映射成匿名用户
- `sync`：写入同步落盘，数据更安全，速度稍慢

注意网段要和客户端实际 IP 对得上：这一行只允许 192.168.0.x 的机器挂载，网段外的客户端会被服务端拒绝。

改完让配置生效：

```bash
exportfs -r
```

**验证点**：`exportfs -r` 无任何报错输出；再执行 `exportfs -v`，应看到 `/export/nfs 192.168.0.0/24(...)` 连同各项参数被列出来。

## 第三步：服务端启动服务

NFS 依赖 RPC 体系，rpcbind 和 nfs-server 两个服务都要起，顺序是先 rpcbind：

```bash
systemctl start rpcbind
systemctl restart nfs-server
```

**验证点**：`rpcinfo -p localhost` 应列出 nfs（2049 端口）和 mountd 的注册行——rpcbind 正常工作时才能看到这张服务表；缺了 rpcbind，这张表是空的，客户端自然连不上。

![配图2](/images/csdn/figures/nfs-csdn134202503-2.png)

设成开机自启，免得重启后共享悄悄失效：

```bash
systemctl enable rpcbind nfs-server
```

## 第四步：客户端查清单、挂载

客户端建好挂载点，先问服务端导出了什么：

```bash
mkdir /data
showmount -e 192.168.0.237
```

**验证点**：`showmount -e` 应列出 `/export/nfs 192.168.0.0/24`——能看到清单说明网络和 RPC 链路都通，这一步通了再挂载，能省掉大半排查时间。

![配图3](/images/csdn/figures/nfs-csdn134202503-3.png)

确认看到 /export/nfs 后执行挂载：

```bash
mount -t nfs 192.168.0.237:/export/nfs /data/
```

**验证点**：`df -hT /data/` 文件系统一列应显示 `nfs`，设备列是 `192.168.0.237:/export/nfs`。

![配图4](/images/csdn/figures/nfs-csdn134202503-4.png)

挂载成功后，往 /data 写的文件实际就落在服务端的 /export/nfs 里。跨机读写验证：

```bash
echo "hello from client" > /data/write-test.txt
```

**验证点**：回服务端 `cat /export/nfs/write-test.txt`，应看到同一行内容——文件确实穿过网络落在了服务端磁盘上。

## 安装后验证与失败出口

整条链路的最终验收就一条：客户端写、服务端读得见。想回退时按逆序拆掉：

```bash
# 客户端卸载
umount /data/
# 服务端停用
systemctl disable --now nfs-server rpcbind
```

三个高频报错，对着现象处理：

- **`mount.nfs: access denied by server`**：客户端 IP 不在导出网段里（容器实测复现过：用 127.0.0.1 挂 192.168.0.0/24 的导出就是这个报错）。核对 /etc/exports 的网段和客户端实际 IP。
- **`showmount` 超时或 clnt_create 失败**：服务端 rpcbind 或 nfs-server 没起全，回服务端看 `systemctl status` 与防火墙 111 端口。
- **挂载成功但写入 Permission denied**：服务端目录权限没放开，检查 `chmod 666` 是否执行，以及 `root_squash` 类参数是否把写入身份压成了无权限用户。

## 小结

回看整条链路：装 nfs-utils、写 /etc/exports、起 rpcbind + nfs-server、客户端 showmount 确认后挂载，每一步都有对应的"应看到什么"。几条经验收个尾：`no_root_squash` 让客户端 root 保留 root 身份，建议只在可信内网开；改 exports 后 `exportfs -r` 即时生效，不必重启 nfs-server；挂载前先 `showmount -e` 问一声，能把挂载失败的排查时间砍掉大半。
