需要在多台 Linux 机器之间共享文件时，NFS 是最省事的方案之一：服务端导出一个目录，客户端把它挂载成本地路径，读写就像操作本地磁盘一样。这篇记录在 AlmaLinux 9.2 和 CentOS 7.6 之间部署 NFS 的完整过程——AlmaLinux 做服务端，CentOS 做客户端。

## 一、安装软件

服务端和客户端都使用 yum 安装 nfs-utils，两台机器执行同一条命令：

```bash
yum install nfs-utils -y
```

## 二、规划

先定好两台机器的角色、目录和 IP，后面的命令都按这个表来：

| 服务器 | 类型 | 目录 | IP地址 |
| --- | --- | --- | --- |
| AlmaLinux | 服务端 | /export/nfs | 192.168.0.237 |
| CentOS | 客户端 | /data | 192.168.0.35 |

## 三、服务端配置

创建导出目录并放开写权限：

```bash
mkdir -p /export/nfs
chmod 666 /export/nfs/
```

`chmod 666` 让所有用户对这个目录可读写，客户端写入时不至于被权限卡住。

![配图](/images/csdn/figures/nfs-csdn134202503.png)

然后把共享规则写进 /etc/exports，添加这一行：

```conf
/export/nfs 192.168.0.0/24(rw,no_root_squash,no_all_squash,sync)
```

这条规则的含义：把 /export/nfs 共享给 192.168.0.0/24 网段，括号里的参数依次是——

- `rw`：允许读写
- `no_root_squash`：客户端 root 用户保留 root 身份，不降权映射
- `no_all_squash`：普通用户保留原有身份，不统一映射成匿名用户
- `sync`：写入同步落盘，数据更安全，速度稍慢

改完让配置生效：

```bash
exportfs -r
```

`exportfs -r` 会重新读取 /etc/exports 并应用变更，不需要重启服务。

接着启动 NFS。它依赖 RPC 体系，所以 rpcbind 和 nfs-server 两个服务都要起：

```bash
systemctl start rpcbind
systemctl restart nfs-server
```

## 四、客户端挂载

客户端先建好挂载点，再查一下服务端导出了哪些目录：

```bash
mkdir /data
showmount -e 192.168.0.237
```

`showmount -e` 会列出服务端的导出清单，确认能看到 /export/nfs 再执行挂载：

```bash
mount -t nfs 192.168.0.237:/export/nfs /data/
```

挂载成功后，往 /data 写的文件实际就落在服务端的 /export/nfs 里。

## 小结

- /etc/exports 括号里的参数直接决定共享权限：`rw` 可读写，`no_root_squash` 让客户端 root 保留 root 身份，`no_all_squash` 不做用户统一映射，`sync` 同步写盘。`no_root_squash` 建议只在可信内网开。
- 修改 exports 后执行 `exportfs -r` 即可生效，不必重启 nfs-server。
- rpcbind 和 nfs-server 两个服务都要启动，缺了 rpcbind 客户端连不上。
- 客户端挂载前先 `showmount -e` 确认导出清单，能省掉大半挂载失败的排查时间。
