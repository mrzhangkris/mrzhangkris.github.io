文章评论、排行榜、投票结果这类内容虽然是动态生成的，更新频率却不高，每次请求都打到后端太浪费。把它们缓存在 Nginx 代理层，后端压力和页面加载速度都会明显改善。这篇给出一套针对这类低频更新动态内容的 Nginx 缓存配置。

## 哪些内容适合这样缓存

先明确哪些动态内容不经常更新：比如用户生成的文章评论、用户排名信息、社区投票结果等。这些内容动态生成但更新频率不高，适合缓存在代理服务器上。

## 缓存策略

对这类内容，推荐用较长的缓存时间，配合主动刷新：内容更新时，通过相关的管理操作清理特定缓存。这样用户大多数时间读到的是缓存内容，内容更新后也能及时看到新的。

## Nginx 配置实例

**配置缓存路径和键：**

```nginx
proxy_cache_path /data/nginx/cache levels=1:2 keys_zone=my_cache:10m max_size=1g inactive=7d use_temp_path=off;

proxy_cache_key "$scheme$request_method$host$request_uri$is_args$args";
```

这里定义了名为 my_cache 的缓存区域：`keys_zone=my_cache:10m` 划出 10MB 共享内存存放缓存键和元数据；`max_size=1g` 限制缓存总大小为 1G；`inactive=7d` 表示内容 7 天内没被访问就从缓存中清除；`use_temp_path=off` 让缓存文件直接写入最终目录，省去一次文件拷贝。缓存键包含了请求方法、主机和 URI，确保不同的请求被正确地分区缓存。

![配图](/images/csdn/figures/nginx-csdn138807677.png)

**配置代理和缓存规则：**

```nginx
server {
    listen 80;
    server_name example.com;

    location /dynamic-content {
        proxy_pass http://backend_server;
        proxy_cache my_cache;
        proxy_cache_valid 200 1h;  # 设置200状态码的响应缓存1小时
        proxy_cache_use_stale error timeout updating http_500 http_502 http_503 http_504;
        add_header X-Cache-Status $upstream_cache_status;
    }
}
```

/dynamic-content 位置就是不常更新动态内容的请求入口。`proxy_cache_valid 200 1h` 把状态码 200 的响应缓存 1 小时；`proxy_cache_use_stale` 让后端出错、超时或返回 5xx 时，Nginx 继续提供旧的缓存内容，保证网站高可用；`X-Cache-Status` 响应头暴露缓存命中状态（$upstream_cache_status，取值如 HIT/MISS），方便排查缓存是否生效。

**主动清理缓存：**

动态内容更新后，需要主动清除对应缓存。这通常要开发自定义脚本，或者使用 nginx_cache_purge 这类第三方模块来实现。

## 注意事项

- 缓存时间要和内容更新频率匹配：示例设了 1 小时，配合"更新时主动清理"，实时性才不受影响。
- proxy_cache_use_stale 是后端故障时的兜底，但提供的是旧内容，对时效敏感的路径要慎用。
- 主动清理能力不会自带，需要提前准备脚本或 nginx_cache_purge 模块。
- 上线后通过 X-Cache-Status 观察命中情况，再回头调缓存时间。
