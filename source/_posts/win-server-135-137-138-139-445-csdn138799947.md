135、137、138、139、445 是 Windows 服务器上最常被扫描的几个端口，也是历史上大规模勒索事件（WannaCry、EternalBlue）的主要入口。封掉它们不需要第三方工具，Windows 自带防火墙就能做到。这篇讲清每个端口对应什么、为什么危险、怎么封、封完怎么验证。

> 注：Windows 防火墙配置为 GUI 操作记录，无法容器化实跑；netsh 命令行方案可脚本化执行（文末给出）。

## 这五个端口各是什么

| 端口 | 协议 | 对应服务 | 危险在哪 |
|------|------|---------|---------|
| 135 | TCP | RPC Endpoint Mapper | 远程过程调用入口，WMI/DCOM 依赖它；被利用做横向移动和远程代码执行 |
| 137 | UDP | NetBIOS Name Service | 名称解析，暴露主机名/域信息，内网侦察常用 |
| 138 | UDP | NetBIOS Datagram Service | 数据报服务，配合 137 做内网广播发现 |
| 139 | TCP | NetBIOS Session Service | 早期 SMB 文件共享通道，445 的前身 |
| 445 | TCP | SMB over TCP | Windows 文件共享核心端口，EternalBlue/WannaCry 的攻击面，**公网暴露 445 = 等被扫** |

一句话：服务器上不做内网文件共享和域环境服务，这五个端口全封无副作用。

## 图形界面操作

在防火墙里新建一条入站规则，步骤如下：

1. 打开控制面板 → 系统和安全 → Windows Defender 防火墙 → 检查防火墙状态，确认**防火墙处于开启状态**；
2. 点击左侧「高级设置」进入防火墙管理器；
3. 左侧选择「入站规则」→ 右侧点击「新建规则」；
4. 规则类型选「端口」→ 下一步；
5. 选择 TCP，并在"特定本地端口"填入 `135,137,138,139,445`（逗号分隔，或分两条规则分别处理 TCP 和 UDP）；
6. 操作选「阻止连接」→ 下一步；
7. 应用配置文件保持默认（域、专用、公用全选）→ 下一步；
8. 名称填 `Block-NetBIOS-SMB`（便于管理），描述可选，完成。

到这里规则就生效了，指向这些端口的入站连接都会被防火墙拦截。UDP 的 137/138 需要额外建一条规则（重复上述步骤，协议选 UDP，端口填 `137,138`）。

## 命令行方案（netsh，可脚本化）

GUI 操作适合单台机器，批量部署用 netsh：

```cmd
:: TCP 端口封禁（需管理员权限的 CMD）
netsh advfirewall firewall add rule name="Block-NetBIOS-SMB-TCP" ^
  dir=in action=block protocol=TCP localport=135,139,445

:: UDP 端口封禁
netsh advfirewall firewall add rule name="Block-NetBIOS-Name-UDP" ^
  dir=in action=block protocol=UDP localport=137,138
```

验证规则是否生效：

```cmd
:: 查看当前入站规则
netsh advfirewall firewall show rule name="Block-NetBIOS-SMB-TCP"
```

验证点：输出显示 `Enabled: Yes`、`Action: Block`。

## 验证封禁真的生效了

封完端口后在另一台机器上用 telnet 或 Test-NetConnection 测试：

```powershell
# PowerShell（在另一台机器上执行）
Test-NetConnection -ComputerName 192.168.1.100 -Port 445
# TcpTestSucceeded = False 即封禁生效

Test-NetConnection -ComputerName 192.168.1.100 -Port 135
# 同上
```

验证点：被封端口的 `TcpTestSucceeded` 返回 False，未封的端口（如 3389）返回 True。

## 注意事项

- **防火墙必须开着**：防火墙关闭时规则不会生效，封了等于没封。确认方法：`netsh advfirewall show allprofiles state`。
- **先查业务依赖**：内网文件共享（SMB）、打印机共享、域控制器的部分服务（AD 复制、组策略下发）会用到 135/139/445，全封之前要评估影响——域环境的域控通常需要保留 135/445，只在成员服务器上封禁。
- **445 的补丁**：封端口只是缓解手段，SMB 漏洞的 Windows 补丁（MS17-010）还是要照常打——万一封禁规则被误删，补丁就是最后一道防线。
- **出站方向**：以上规则只拦入站（`dir=in`），不拦出站。内网横向移动防护需要在所有成员服务器上都加规则，不能只在边界设备上封。
- **组策略批量部署**：域环境建议把防火墙规则写进组策略（GPO），统一推送到所有服务器，避免遗漏。

Windows 防火墙封端口这件事，技术难度几乎为零，真正的功夫在"封之前查依赖"和"封之后验生效"——netsh 一条命令能脚本化完成，但验证那一步一定不能省。
