负载均衡就是把网络或应用流量分配到多台服务器上，让资源利用更充分、吞吐量更大、响应更快，也避免单台机器被打挂。Nginx 擅长七层（应用层）负载均衡，配合 stream 模块也能做四层（传输层）。这篇分别记录两种负载均衡的使用场景和 Nginx 配置示例。

## 四层负载均衡（TCP/UDP）

四层负载均衡工作在传输层，主要处理 TCP 和 UDP 协议，转发决策基于 IP 地址、TCP 端口这类传输层信息，不深入应用内容本身。省去了解析协议内容的开销，处理速度快。

使用场景：

- **数据传输服务**：如 FTP 流量的负载均衡，或数据库复制流量中的负载均衡。
- **邮件传输服务**：如 SMTP 或 IMAP 服务的负载均衡。
- **实时通讯**：为 VoIP（如 SIP 服务）或在线游戏服务器分摊流量。

Nginx 处理四层负载均衡要依赖 stream 模块（ngx_stream_core_module）。

> 注：原文称其为"第三方模块"；该模块自 Nginx 1.9.0 起已官方内置，编译时加 --with-stream 参数启用。存疑处以官方文档为准。

配置示例：

![配图](/images/csdn/figures/nginx-csdn138809029.png)

```nginx
stream {
    upstream backend {
        server backend1.example.com:12345;
        server backend2.example.com:12345;
    }

    server {
        listen 12345;
        proxy_pass backend;
        proxy_next_upstream off;
    }
}
```

stream 块与 http 块平级：upstream backend 定义了两台 12345 端口的后端；server 监听本机 12345 端口，把收到的 TCP 连接转发给 backend 组。`proxy_next_upstream off` 关闭失败重试——转发失败时不再尝试下一台后端。

## 七层负载均衡（HTTP/HTTPS）

七层负载均衡工作在应用层，能基于 HTTP 头信息、URL、Cookie 等内容做智能路由，适合更复杂的路由策略。

使用场景：

- **Web 应用**：按 URL 或请求类型把流量分配到专门的后端服务。
- **API 路由**：根据 API 端点的不同，把请求分发到不同的后台服务。
- **个性化内容分发**：根据用户登录状态或位置信息提供定制化内容。

配置示例：

```nginx
http {
    upstream myapp1 {
        server app1.example.com;
        server app2.example.com;
    }

    server {
        listen 80;
        server_name www.example.com;

        location / {
            proxy_pass http://myapp1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        }
    }
}
```

upstream myapp1 定义后端组，location / 把所有请求代理给这组服务器。三条 proxy_set_header 是反向代理的常规动作：把原始 Host、客户端真实 IP（X-Real-IP）和转发链（X-Forwarded-For）传给后端，后端的日志和业务逻辑才能拿到真实的客户端信息。

## 小结

- 四层只看 IP 和端口，转发快但看不到内容；七层解析 HTTP，能按 URL、Cookie 做精细路由，开销也更大。
- 七层负载均衡 Nginx 开箱即用；四层要靠 stream 模块，编译 Nginx 时记得带上 --with-stream。
- 两种方式各有适用面，按协议类型和路由粒度需求选择，不必二选一。
