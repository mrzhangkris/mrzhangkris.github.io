Nginx 是一款高性能的 HTTP 和反向代理 Web 服务器，同时也是 IMAP/POP3/SMTP 代理服务器，常被用来扛大量并发连接。它的所有能力都通过配置文件组织起来，把常用配置项的用途和坑摸清楚，是玩转 Nginx 的前提。本文按配置文件的结构，把最常用的配置项过一遍。

## 配置文件结构

主配置文件通常位于 `/etc/nginx/nginx.conf` 或 `/usr/local/nginx/conf/nginx.conf`，结构上分为全局块、events 块和 http 块：

```nginx
# 全局块
user www;
worker_processes 1;

error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

# events 块
events {
  worker_connections 1024;
}

# http 块
http {
  include /etc/nginx/mime.types;
  default_type application/octet-stream;

  log_format main '$remote_addr - $remote_user [$time_local] "$request" '
    '$status $body_bytes_sent "$http_referer" '
    '"$http_user_agent" "$http_x_forwarded_for"';

  access_log /var/log/nginx/access.log main;

  sendfile on;
  tcp_nopush on;
  tcp_nodelay on;
  keepalive_timeout 65;
  types_hash_max_size 2048;

  include /etc/nginx/conf.d/*.conf;
}
```

全局块管进程和日志这类整体行为，events 块管连接处理，http 块管所有 HTTP 相关的配置，日常改得最多的就是 http 块。

## 全局块配置项

### user

定义工作进程运行所使用的用户和用户组：

```nginx
user www;
```

用途是让 Nginx 以安全的权限运行，避免漏洞被利用后拿到高权限。这里应选择最低权限的用户，尽可能减小安全风险。

### worker_processes

定义工作进程数量，一般设置为服务器的 CPU 核心数：

```nginx
worker_processes auto;
```

`auto` 让 Nginx 自动探测核心数，充分利用多核 CPU。进程数设得过多只会浪费资源，按实际核心数来即可。

### error_log

定义全局错误日志的路径和级别：

```nginx
error_log /var/log/nginx/error.log warn;
```

排障时最先看的就是这个文件。级别通常设为 warn 或更高，避免日志文件膨胀得太快。

## events 块配置项

### worker_connections

定义每个工作进程可处理的最大连接数：

```nginx
events {
  worker_connections 1024;
}
```

这是控制并发的关键参数。值可以设大一些，但前提是服务器的资源足以处理这些连接，否则只是把压力从 Nginx 挪到了操作系统上。

## http 块配置项

### include

包含其他配置文件：

```nginx
include /etc/nginx/conf.d/*.conf;
```

把不同站点的配置拆到独立文件里，主配置保持干净。注意被包含文件的路径要正确、内容要无误，一处语法错误会让整个 reload 失败。

### server 块

定义一个虚拟主机：

```nginx
http {
  server {
    listen       80;
    server_name  example.com;
    root         /var/www/html;

    access_log   /var/log/nginx/example.access.log main;

    location / {
      try_files $uri $uri/ =404;
    }
  }
}
```

通过不同的域名或端口配置多个虚拟主机，实现多站点共存。每个虚拟主机的 `server_name` 要保持唯一，避免冲突。

### location 块

匹配请求路径，执行特定操作：

```nginx
location /images/ {
  alias /data/images/;
}
```

这是定义路径处理规则的地方。一个常见坑：`alias` 指令的路径必须以 `/` 结尾。

### log_format 和 access_log

定义访问日志格式和存储路径：

```nginx
log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                '$status $body_bytes_sent "$http_referer" '
                '"$http_user_agent" "$http_x_forwarded_for"';

access_log /var/log/nginx/access.log main;
```

访问日志是分析流量、诊断问题的主要数据来源。格式里保留必要字段，日志路径确保 Nginx 有写权限。

### gzip

启用 gzip 压缩，减少传输数据量：

```nginx
gzip on;
gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;
```

压缩响应内容能明显减少带宽占用。`gzip_types` 挑文本类内容即可，图片这类已经压缩过的文件不要再压，白白消耗 CPU。

## 反向代理配置

把请求转发给后端应用，同时隐藏后端信息：

![配图](/images/csdn/figures/nginx-csdn139165845.png)

```nginx
server {
  listen 80;
  server_name myapp.example.com;

  location / {
    proxy_pass http://localhost:5000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

这套配置把客户端请求转给 `localhost:5000` 的后端服务。`proxy_set_header` 那几行不能省——它们把原始请求的 Host、来源 IP、协议信息带给后端，否则后端看到的都是 127.0.0.1。

## SSL/TLS 加密配置

### 基本 HTTPS 配置

监听 443 端口并启用 SSL：

```nginx
server {
  listen 443 ssl;
  server_name example.com;

  ssl_certificate /etc/nginx/ssl/example.com.crt;
  ssl_certificate_key /etc/nginx/ssl/example.com.key;

  location / {
    root /var/www/html;
    index index.html;
  }
}
```

为网站加上 TLS 加密，保证传输的安全性和隐私性。证书和私钥路径要正确，且 Nginx 进程有读取权限。

### 强制 HTTPS

用 `return` 指令把 HTTP 请求重定向到 HTTPS：

```nginx
server {
  listen 80;
  server_name example.com;
  return 301 https://$server_name$request_uri;
}
```

注意这段重定向规则要放在监听 80 端口的 server 块里，而不是 443。

### HSTS

用 `add_header` 配置 HTTP 严格传输安全：

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

（加在 443 的 server 块中。）这条响应头让浏览器在一年内强制走 HTTPS 连接，防御劫持。开启 HSTS 之前，先确认网站已经能稳定通过 HTTPS 访问——一旦浏览器记住了这个头，回退到 HTTP 会被拒绝。

## 负载均衡

Nginx 可以把请求分发到多个后端服务器。

### 轮询负载均衡

```nginx
http {
  upstream backend {
    server backend1.example.com;
    server backend2.example.com;
    server backend3.example.com;
  }

  server {
    listen 80;
    server_name example.com;

    location / {
      proxy_pass http://backend;
    }
  }
}
```

`upstream` 定义后端池，默认轮询分发。各服务器性能不均时，可以用 `weight` 参数分配不同权重。

### 简单健康检查

通过 `proxy_next_upstream` 实现：

```nginx
location / {
  proxy_pass http://backend;
  proxy_next_upstream error timeout http_502 http_503 http_504;
}
```

后端报错或超时，Nginx 会把请求转给池里的下一个服务器，提高整体可靠性。故障返回码可以按需增加。

## 缓存配置

缓存后端响应，加速常用数据访问：

```nginx
http {
  proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=my_cache:10m max_size=1g inactive=60m use_temp_path=off;

  server {
    listen 80;
    server_name example.com;

    location / {
      proxy_cache my_cache;
      proxy_pass http://backend;
      proxy_cache_bypass $http_cache_control;
      proxy_no_cache $http_cache_control;

      add_header X-Cache-Status $upstream_cache_status;
    }
  }
}
```

`proxy_cache_path` 声明缓存存储路径和键区（必须先配置），`proxy_cache` 在 location 里启用。`X-Cache-Status` 响应头方便确认请求是命中缓存还是回源。

## 常见安全配置

### 隐藏 Nginx 版本

```nginx
http {
  server_tokens off;
}
```

一行配置，避免版本号泄露带来的针对性攻击，简单有效。

### 限制请求速率和连接数

```nginx
http {
  limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
  limit_conn_zone $binary_remote_addr zone=addr:10m;

  server {
    listen 80;
    server_name example.com;

    location / {
      limit_req zone=one burst=5;
      limit_conn addr 10;
      proxy_pass http://backend;
    }
  }
}
```

按来源 IP 限制请求速率和并发连接数，是对抗 DDoS 的基础防线。参数要按实际业务调，设得太紧会误伤正常用户。

## 注意事项

- 改完配置先 `nginx -t` 验证语法再 reload，`include` 进来的文件同样会被检查。
- `alias` 路径必须以 `/` 结尾，少了会出 404。
- 反向代理务必带上 `proxy_set_header` 系列，否则后端拿到的客户端信息全是错的。
- HSTS 开了就难以快速回退，上线前确认 HTTPS 已稳定。
- 限速限连参数宁松勿紧，观察日志再逐步收紧。
