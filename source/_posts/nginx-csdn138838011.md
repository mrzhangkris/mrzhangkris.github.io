排查 Nginx 的性能问题和异常退出，第一步通常是搞清楚它内部的进程都在干什么。Nginx 是一个高性能的 Web 服务器和反向代理服务器，采用多进程模型来优化并发处理和稳定性。它的进程结构主要由以下几部分组成。

## 三类进程

**主进程（Master Process）**：管理其他所有进程（工作进程和辅助进程），包括启动、监控和关闭它们。主进程还负责读取和验证配置文件、处理信号以及进行日志记录。日常操作里的 reload、stop 信号，都是主进程在接。

**工作进程（Worker Processes）**：Nginx 实际处理客户端请求的地方。每个工作进程独立运行，处理从主进程接收的连接。工作进程的数量通常与服务器 CPU 核心数相匹配，以实现高效的负载均衡和并行处理。

**缓存相关进程（Cache Manager 和 Cache Loader）**：这两个辅助进程负责管理和优化文件缓存，确保缓存数据的高效更新和加载。

## 单进程结构 vs 多进程结构

**单进程结构**：服务器的所有任务（连接处理、数据处理、日志记录等）都在一个单一的进程中完成。这种结构简单、资源占用低，但通常无法有效利用多核心系统，高负载时容易成为性能瓶颈。

**多进程结构**：Nginx 采用的模型，可以充分利用现代多核硬件。多个工作进程并行运行在多个核心上，处理请求的能力显著提高；每个进程独立运行，也增强了系统的稳定性。

## 为什么选多进程而不是多线程

**隔离性和稳定性**：进程之间的隔离性优于线程。一个工作进程失败，主进程可以立即重启它，不会影响其他进程——这比多线程模型更稳。

**内存管理**：每个进程有自己独立的内存空间，内存泄漏的影响被限制在单个进程内。线程则共享内存空间，一旦泄漏，可能波及所有线程。

**性能优势**：多进程模型能更好地利用多核服务器，尤其在高负载环境下。每个进程可以运行在不同的 CPU 核心上，有效分散处理压力。

## 小结

- master 负责管理和验证配置，worker 负责真正干活，缓存由 cache manager/loader 两个辅助进程打理。
- worker 数量一般和 CPU 核心数对齐，盲目调大并不会带来更高吞吐。
- 多进程换来的隔离性是 Nginx 稳定性的基础：单点崩溃可被主进程直接拉起。
- 理解进程结构对后续做性能优化和故障排查是前置知识。
